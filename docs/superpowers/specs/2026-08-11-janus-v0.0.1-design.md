# Janus v0.0.1 design

## Product intent

Janus is an approachable desktop agent workspace built on t3code. It keeps t3code's local agent harness, provider subscriptions, repositories, checkpoints, previews, diffs, and terminal access, but presents them through a calm chat-first interface for both software developers and knowledge workers.

The prototype succeeds when a first-time user understands three things without reading documentation:

1. choose a workspace;
2. describe the outcome they want;
3. supervise progress and review the finished work.

Janus does not pretend that technical work disappeared. It moves implementation detail into progressive disclosure so people can reach it when it is useful without making it the product's dominant visual language.

## Research synthesis

- t3code already supplies the hard runtime: an event-sourced orchestration server, authenticated RPC boundary, local provider processes, workspace and version-control operations, and clients for web, desktop, and mobile. Replacing that engine would add risk without improving the v0.0.1 experience.
- [Claude Cowork](https://www.anthropic.com/product/claude-cowork) frames the product around outcomes, selected folders, finished deliverables, and human oversight. Its strongest lesson is vocabulary and hierarchy rather than visual imitation.
- [The Codex app](https://openai.com/index/introducing-the-codex-app/) treats long-running agent work as a conversation and command center instead of a terminal session.
- [WAI-ARIA](https://www.w3.org/WAI/standards-guidelines/aria/) requires custom controls, changing status, and chat-like live regions to remain keyboard and assistive-technology accessible.
- GitHub's [artifact attestations](https://docs.github.com/en/actions/concepts/security/artifact-attestations) are useful for release provenance, while checksums remain the simplest portable integrity record for every downloaded artifact.

## Chosen approach

Use a presentation-shell transformation, not an engine rewrite and not a color-only reskin.

- Preserve server, contracts, provider drivers, persistence, routing, checkpointing, preview, diff, git, terminal, and permission behavior.
- Change the desktop/web visual hierarchy, default vocabulary, empty states, composer, task timeline presentation, and visible product identity.
- Keep developer capabilities available in context menus, toolbars, drawers, and secondary panels.
- Avoid mass-renaming internal `@t3tools` packages, RPC fields, database names, and legacy environment variables in v0.0.1. Those are compatibility contracts, not visible product identity.
- Leave the inherited mobile client functional but outside this redesign's acceptance scope.

## Experience architecture

### Navigation

The sidebar becomes a workspace and task history, not a project/thread debugger.

- Brand: Janus.
- Primary action: `New task`.
- `Projects` becomes `Workspaces` in prominent user-facing copy.
- `Threads` becomes `Tasks` where the term describes the user's work. Internal types and URLs remain unchanged.
- Git pull requests, usage, provider updates, and settings remain available but visually secondary.

### New-task canvas

The first meaningful screen uses generous whitespace and an editorial center column.

- Headline: outcome-oriented language such as `What would you like to accomplish?`
- Supporting copy explains that Janus can work with files, research, documents, data, and code in the selected workspace.
- The workspace picker is visible and plain-language.
- A compact starter rail demonstrates credible tasks: synthesize research, prepare a brief, organize files, analyze a dataset, or build/fix software.
- Starters populate the composer; they do not create fake results or bypass provider selection.

### Composer

The composer reads as a chat input before it reads as a command surface.

- Larger minimum height and comfortable text measure.
- Plain-language placeholder first; advanced `@`, `$`, and `/` syntax remains discoverable through supporting copy/tooltips.
- Provider/model, reasoning/mode, permissions, and context indicators remain functional in a quieter footer.
- Focus rings, keyboard shortcuts, pending approvals, user questions, attachments, and error states are preserved.

### Task conversation

- User prompts and assistant responses use a readable conversation measure with clearer role separation.
- Progress and tool activity are summarized as calm work updates. Raw terminal output remains available through existing drawers and detail surfaces.
- Changed files, diffs, plans, approvals, previews, and artifacts keep their existing behavior.
- Header hierarchy leads with task title and workspace. Git and editor controls are secondary actions.
- Streaming/status announcements retain accessible semantics and do not steal focus.

### Visual system

Janus is light-first with a complete dark counterpart.

- Warm paper canvas, ivory raised surfaces, charcoal text, and one restrained moss/forest action color.
- Dark mode uses tinted charcoal rather than pure black.
- Sans typography remains locally available and CSP-safe; headings gain stronger size, tracking, and weight hierarchy without adding a network font dependency.
- Borders are quieter, radii vary by hierarchy, shadows are tinted and sparse, and a subtle grain prevents flatness.
- Code, diffs, and terminal surfaces keep monospace typography and higher contrast because those are the places where terminal conventions are useful.
- Motion is short and functional, with `prefers-reduced-motion` respected.

## Desktop identity matrix

Janus must not collide with T3 Code installations or state.

| Surface                     | Janus v0.0.1 value                                               |
| --------------------------- | ---------------------------------------------------------------- |
| Display name                | `Janus` (`Janus Dev` in development)                             |
| Bundle/application ID       | `com.zgbrenner.janus` (`com.zgbrenner.janus.dev` in development) |
| Executable / Linux WM class | `janus` / `janus-dev`                                            |
| URL scheme                  | `janus` / `janus-dev`                                            |
| User-data directory         | `janus` / `janus-dev`                                            |
| Preview partition prefix    | `persist:janus-preview-`                                         |
| Update repository           | `zgbrenner/janus`                                                |
| Artifact prefix             | `Janus-<version>-<arch>`                                         |
| Release name                | `Janus v<version>`                                               |

The implementation must update tests for these boundaries and must not silently read or migrate T3 Code user data. Existing internal protocol or environment names may remain only when they are not operating-system identity or visible branding.

## Brand assets and attribution

- Create a restrained Janus mark using original vector geometry that works at favicon, installer, and application-icon sizes.
- Replace visible T3 wordmarks and public application icons used by the desktop/web prototype.
- Preserve the MIT license.
- Add an explicit upstream attribution section linking to `pingdotgg/t3code` and explaining that Janus is an independent fork.
- Do not imply endorsement by T3, Anthropic, or OpenAI.

## CI and release design

The inherited pipeline is not portable because it assumes private runners and upstream relay, Clerk, npm, Vercel, Discord, and release-bot credentials. Janus v0.0.1 uses GitHub-hosted infrastructure and publishes only GitHub desktop artifacts.

### Pull request and main gates

- dependency install with the repository's locked package manager and Node version;
- formatting and lint;
- workspace typecheck;
- unit/integration tests;
- desktop/web build and preload-contract check;
- Rust formatting/tests for the resource monitor;
- release-smoke contract;
- dependency review on pull requests;
- CodeQL for JavaScript/TypeScript and GitHub Actions;
- workflow concurrency, least-privilege permissions, timeouts, and no persisted checkout credentials where writes are unnecessary.

### Tagged release

- Trigger only on semantic `v*.*.*` tags and optional manual dispatch for the same explicit version.
- Run preflight gates before packaging.
- Build unsigned desktop artifacts on GitHub-hosted macOS, Windows, and Linux runners when signing credentials are absent; report that status honestly.
- Merge/update metadata required by `electron-updater`.
- Generate SHA-256 checksums for release assets.
- Upload immutable workflow artifacts, create provenance attestations where supported, and publish one GitHub release only after all required builds succeed.
- Do not deploy the upstream relay or hosted web app, publish the upstream `t3` npm package, schedule nightlies, post to Discord, or write version commits with an unavailable release bot.

## Testing and acceptance

### Local gates

- focused tests for copy, task starters, identity resolution, artifact naming, protocol/user-data isolation, and release metadata;
- web build, desktop build, typecheck, lint/format, workspace tests, Rust checks, and release smoke;
- `git diff --check` and a secret-pattern review.

### Rendered desktop QA

The flow under test is: launch Janus -> choose or use a workspace -> create a task from the welcoming composer -> observe the task conversation and progress -> open an advanced developer surface -> return to the conversation.

Validate at desktop window widths representing compact and wide layouts, in light and dark themes:

- correct app title and Janus identity;
- meaningful non-blank first screen;
- no framework overlay or relevant console errors;
- visible focus and keyboard operation;
- no clipping, overflow traps, or unreadable hierarchy;
- task starter interaction populates the real composer;
- provider/model and advanced developer controls remain reachable;
- terminal/diff surfaces still render when invoked.

### Release acceptance

- main commit and `v0.0.1` tag resolve to the intended source revision;
- required GitHub Actions checks pass;
- the public release is published with expected platform assets and checksum manifest;
- at least the Windows artifact is downloaded and smoke-tested on the current Windows host when an unsigned build can run; macOS/Linux runtime execution remains CI-build evidence unless corresponding hosts are available;
- signing, notarization, package-store distribution, and real provider subscription E2E are reported separately and never inferred from build success.

## Error handling and safety

- Existing permission and approval behavior remains authoritative.
- Janus never converts a provider error into a success state.
- Missing provider authentication is explained in plain language with a settings path.
- Advanced commands and terminal output are not hidden when needed for diagnosis.
- Release jobs fail closed when artifacts, hashes, or preflight results are missing.
- No credentials are added to the repository or echoed into logs.

## Deferred work

- document-native editors, connector marketplace, and rich artifact canvases;
- mobile-specific Janus redesign;
- migration from existing T3 Code user data;
- package-store publishing, signing, and notarization;
- hosted Janus relay/web service;
- renaming internal packages and protocol contracts.

These are intentionally excluded so v0.0.1 can prove the approachable desktop shell without weakening the inherited agent runtime.
