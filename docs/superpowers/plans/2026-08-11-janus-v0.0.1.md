# Janus v0.0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a polished, chat-first Janus desktop prototype on t3code's existing multi-provider engine, with an isolated application identity and a fork-native GitHub CI/release pipeline.

**Architecture:** Keep the event-sourced server, RPC contracts, provider drivers, persistence, routing, checkpointing, git, terminal, preview, and diff behavior unchanged. Change only the desktop/web presentation shell and operating-system-visible identity, then replace upstream-specific automation with GitHub-hosted quality and release workflows.

**Tech Stack:** React 19, TypeScript, TanStack Router, Tailwind CSS 4, Effect, Vite+, Electron 41, electron-builder 26, Vitest, GitHub Actions, Rust resource monitor.

## Global Constraints

- The accepted design is `docs/superpowers/specs/2026-08-11-janus-v0.0.1-design.md`.
- Preserve internal `@t3tools` package names, RPC/data contracts, provider behavior, and legacy environment-variable names unless an operating-system identity boundary requires change.
- Visible product name is `Janus`; prominent user vocabulary is `Workspaces` and `Tasks`.
- Light mode uses warm paper/ivory surfaces with one restrained moss/forest action color; dark mode uses tinted charcoal rather than pure black.
- Preserve keyboard behavior, focus visibility, accessible status announcements, CSP, routes, permission flows, and advanced terminal/git/model controls.
- Desktop identity must not read T3 Code user data or claim the `t3code` protocol.
- Release scope is GitHub desktop artifacts only: no relay/web deployment, npm publish, scheduled nightly, Discord notification, or release-bot write.
- Preserve `LICENSE` and add upstream attribution to `pingdotgg/t3code`.
- Do not add credentials, signing material, fake provider results, or placeholder copy.

### Task 3: Fork-native CI, release, and documentation

**Files:** Automation and documentation unit only.

**Interfaces:**

- Produces:

```yaml

  - check
  - test
  - desktop_build
  - rust
  - release_smoke
release_platforms:
  - macos-arm64
  - macos-x64
  - linux-x64
  - windows-x64
```

The tag version is the single release version source; release publication must fail if any required artifact or checksum is missing.


- [ ] **Step 3: Replace CI with GitHub-hosted gates**

Use `ubuntu-24.04`, `windows-2025`, and `macos-15`/supported GitHub-hosted labels; set top-level `contents: read`; use `persist-credentials: false` in read-only jobs; set explicit job timeouts and concurrency; run locked install, check, typecheck, test, desktop build/preload probe, Rust format/test, and release smoke.

- [ ] **Step 4: Add the security workflow**

Use GitHub's maintained CodeQL and dependency-review actions with least privilege. Dependency review runs on pull requests; CodeQL runs on pull requests, main pushes, weekly schedule, and manual dispatch. Do not request write permissions except `security-events: write` for result upload.
